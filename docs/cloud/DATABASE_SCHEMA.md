# CLOUD.0 — Database Schema

Дата: 2026-07-01
Статус: schema design; migrations/code не создавались.

## Цель

Развить `DATABASE_READINESS.md` в конкретную PostgreSQL-oriented schema для server/cloud MVP.
Схема строится на stable IDs, tenant isolation и auditability. Display names не являются primary
keys.

## ID Policy

Recommended:

- UUIDv7 or UUID primary keys generated by backend/database.
- `legacy_*` fields preserve YAML IDs/names during migration.
- Every business table includes `tenant_id`, except global `users` and `telegram_accounts`.

## Tables

### `tenants`

Columns:

- `tenant_id uuid primary key`
- `name text not null`
- `status text not null check (status in ('active', 'archived'))`
- `default_currency text not null default 'RUB'`
- `created_at timestamptz not null`
- `updated_at timestamptz not null`

Indexes:

- `idx_tenants_status(status)`

### `users`

Columns:

- `user_id uuid primary key`
- `display_name text not null`
- `status text not null check (status in ('active', 'disabled'))`
- `created_at timestamptz not null`
- `updated_at timestamptz not null`

### `telegram_accounts`

Columns:

- `telegram_account_id uuid primary key`
- `telegram_user_id bigint not null unique`
- `user_id uuid not null references users(user_id)`
- `username text`
- `first_name text`
- `last_name text`
- `language_code text`
- `created_at timestamptz not null`
- `last_seen_at timestamptz`

Indexes:

- unique `telegram_user_id`
- `idx_telegram_accounts_user_id(user_id)`

### `participants`

Columns:

- `participant_id uuid primary key`
- `tenant_id uuid not null references tenants(tenant_id)`
- `linked_user_id uuid references users(user_id)`
- `display_name text not null`
- `normalized_display_name text not null`
- `status text not null check (status in ('active', 'archived'))`
- `created_at timestamptz not null`
- `updated_at timestamptz not null`

Constraints/indexes:

- `idx_participants_tenant_status(tenant_id, status)`
- unique active display name per tenant should be implemented with partial unique index:
  `(tenant_id, normalized_display_name) where status = 'active'`.

### `participant_aliases`

- `participant_alias_id uuid primary key`

- `participant_id uuid not null references participants(participant_id)`
- `alias text not null`
- `normalized_alias text not null`
- `source text not null check (source in ('yaml_migration', 'telegram_input', 'manual'))`
- `created_at timestamptz not null`

Indexes:

- `idx_participant_aliases_lookup(tenant_id, normalized_alias)`
- `idx_participant_aliases_participant(participant_id)`

### `categories`

Columns:

- `category_id uuid primary key`
- `tenant_id uuid not null references tenants(tenant_id)`
- `display_name text not null`
- `normalized_display_name text not null`
- `status text not null check (status in ('active', 'archived'))`
- `created_at timestamptz not null`
- `updated_at timestamptz not null`

Indexes:

- `idx_categories_tenant_status(tenant_id, status)`
- partial unique `(tenant_id, normalized_display_name) where status = 'active'`.

### `purchases`

Columns:

- `purchase_id uuid primary key`
- `tenant_id uuid not null references tenants(tenant_id)`
- `purchase_date date`
- `purchase_name text not null`
- `amount numeric(14, 2) not null check (amount > 0)`
- `currency text not null default 'RUB'`
- `payer_participant_id uuid not null references participants(participant_id)`
- `category_id uuid references categories(category_id)`
- `comment text`
- `status text not null check (status in ('open', 'settled', 'deleted'))`
- `settlement_period_id uuid`
- `legacy_purchase_id text`
- `created_by_user_id uuid references users(user_id)`
- `created_at timestamptz not null`
- `updated_at timestamptz not null`
- `version integer not null default 1`

Indexes:

- `idx_purchases_tenant_date(tenant_id, purchase_date)`
- `idx_purchases_tenant_status(tenant_id, status)`
- `idx_purchases_tenant_payer(tenant_id, payer_participant_id)`
- `idx_purchases_tenant_period(tenant_id, settlement_period_id)`

Constraint:

- FK `(settlement_period_id)` to `settlement_periods` can be added after both tables exist, or
  deferred.

- `purchase_id uuid not null references purchases(purchase_id)`

### `settlement_periods`

Columns:

Indexes:

## Transaction Requirements

Must be atomic:

- add purchase + purchase participants + audit log;
- edit purchase + audit log;
- close settlement period + mark purchases settled + snapshot rows + audit log;
- reopen period + mark purchases open + audit log;
- report metadata + audit log.

## Historical Snapshot Rules

Settlement period reports must use stored snapshot settlements. Do not recalculate historical
settlements during report generation.

`snapshot_json` should store:

- participant IDs;
- display labels at close time;
- settlement amounts;
- total amount;
- close metadata.

## YAML Offline Compatibility

This schema does not replace YAML immediately. Desktop CLI/GUI keep using YAML through
`YamlExpenseRepository` until services are extracted and adapters are wired.

## CLOUD.0 Prohibitions

No migrations are created in CLOUD.0. No PostgreSQL server is provisioned. No secrets are added.
